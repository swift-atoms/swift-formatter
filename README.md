# swift-formatter

Use this package to turn a value into another value, usually a `String`, with a formatter that is chosen and configured separately from the value. Start from `Formatter.Protocol`; wrap a closure with `Format<Input, Output, Failure>`, give a type one canonical formatter with `Formattable`, and run two formatters side by side by pairing them in a `Pair<First, Second>`. The traits add ready-made formatters: `Formatter.Number` and `Formatter.Duration<Numeric>` for numbers and durations, `Radix.Formatter` for integers in a base, `Byte.Formatter`, `Binary.Formatter<Bytes>` and `Byte.Size.Formatter<Count>` for bytes, byte streams and byte counts, and `Bit.Formatter<Carrier>` for bit masks. To write into a buffer, use swift-serializer instead; to read text back into values, use swift-parser.

## Laws

- A `Pair<First, Second>` of formatters formats `first` before `second`. When `first` fails, `second` never runs and the failure is `.left`; when only `second` fails, it is `.right`.
- `Formatter.Number` works on the shortest decimal that round-trips the `Double`, not on its exact binary value, and never prints an exponent. Without `fractionDigits` it drops trailing zeros; with them it pads with zeros or rounds the decimal digits by `rounding`. `.percent` shifts the decimal point two places, so no floating-point multiplication happens, and appends `%`. NaN prints `nan` and infinities print `inf` or `-inf`. `padding` is the fewest integer digits written: it makes them up with leading zeros after rounding and never truncates, and the sign goes in front of the zeros: `-005`. A `Formatter.Number.Grouping` splits the integer digits, padding zeros included, from the decimal point leftwards: `primary` digits next to it and `secondary` digits in every group beyond (`size:` sets both), each a `Cardinal` of at least 1, so 1,234,567 and 12,34,567 are both one grouping. The separator goes only between two groups, never between the sign and the digits, and fraction digits, `nan` and `inf` are never grouped. Removing the separators gives the ungrouped output. The decimal separator is always `.`.
- `Formatter.Duration<Numeric>` with unit `.auto` picks the unit from the magnitude, so negative durations pick the same unit as positive ones: below 1 µs it uses nanoseconds, below 1 ms microseconds, below 1 s milliseconds, and seconds otherwise. The scaled value passes through `Double` before it reaches `numeric`.
- `Radix.Formatter` writes lowercase digits. Zero padding counts digits only. It never truncates, and the prefix and then the sign are put in front of the padded digits, so the output reads `-0x0005`. Only `.prefix` turns the prefix on. `.always` writes `+0` for zero.
- `Byte.Formatter` always writes the number of digits that 255 needs in its radix: 2 in hexadecimal, 3 in decimal, 8 in binary. `Binary.Formatter<Bytes>` puts the separator only between bytes, so an empty stream gives an empty string.
- `Byte.Size.Formatter<Count>` reads the tiers in order and stops at the first tier the value does not reach, so the tiers must be listed in ascending exponent order. Values above the top tier stay on the top tier, and values below the first tier use the bare unit. Fraction digits are cut off toward zero, not rounded, and a `precision` of 0 also drops the decimal point. A scale whose `base` does not fit in `Count.Magnitude` traps.
- `Bit.Formatter<Carrier>` always writes `Carrier.bitWidth` digits. Groups are counted from the start of the output after `order` is applied, and a group size of at least the width adds no separator.
- The converting `formatted(_:)` overloads on `BinaryInteger` and `BinaryFloatingPoint` (the `Conversions` trait) and on `Tagged` convert with `F.Input(_:)`. An integer that does not fit in the formatter's input type traps.
